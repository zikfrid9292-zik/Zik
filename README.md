# Bitrix Local Agent V3

Безопасное ядро локального агента Bitrix24. Текущая итерация реализует только
READ-only discovery: она не создаёт, не изменяет и не удаляет объекты портала.

## Состояние входных данных

В текущем Git-репозитории не было исходников V1/V2/V3 (только заголовок README),
а файл `.env` и переменная `BITRIX_WEBHOOK_URL` отсутствовали. Поэтому фактическая
инвентаризация портала `Test` пока не выполнена. Код ниже готовит повторяемое
исследование, которое можно запустить после возврата исходников и локального `.env`.

## Безопасность

* `BitrixClient.call_read()` пропускает только явно классифицированные READ-методы.
* Любая неизвестная операция fail-closed; WRITE/DELETE этим клиентом вызвать нельзя.
* URL webhook никогда не попадает в исключения или audit log.
* Параметры рекурсивно очищаются от ключей с секретами.
* SQLite хранится локально в `var/agent-v3.sqlite3` и исключён из Git.

## Запуск исследования

```bash
cp .env.example .env
# заполнить BITRIX_WEBHOOK_URL локально, не коммитить
python -m bitrix_agent.cli discover-test --db var/agent-v3.sqlite3
```

Команда безопасно проверит доступность нужных методов через `method.get`, scopes,
проект `Test`, одноимённые задачи, поля задач, шаблоны и шаблоны бизнес-процессов.
Каждый вызов и нормализованный результат сохраняются в `experiments`/`bitrix_map`.
Если конкретный list-метод шаблонов недоступен, это фиксируется как результат, а не
заменяется предположением.

## Предварительная архитектура решения `Test`

Предпочтительный вариант после проверки портала — штатная цепочка Gantt
Finish-to-Start между подзадачами. Bitrix24 штатно переносит зависимую плановую дату
при переносе ведущей задачи; локальный обработчик нужен только если фактическое
поведение тарифа/портала не пройдёт интеграционную проверку.

Сравнение вариантов и неизменяемый PREVIEW находятся в
`docs/test-project-preview.md`. Это план, **не подтверждение** и не выполнение.
